# Crazsix Store Workspace

เว็บจัดการสต็อกเสื้อผ้า การขาย และบัญชีร้าน Crazsix พร้อมหน้าตา Liquid Glass ที่รองรับเดสก์ท็อปและมือถือ

เว็บไซต์: https://crazsix-stock.web.app

## ฟีเจอร์

- ภาพรวมมูลค่าสต็อก เงินเข้า–ออก 6 เดือน สินค้าใกล้หมด สินค้ารอรับ และยอดค้างชำระ
- สินค้าหลายสี/ไซส์ แยกมือหนึ่ง–มือสอง รูปแยกตามสี เพิ่มหลายสินค้าและเติมสต็อกแบบต้นทุนเฉลี่ย
- ต้นทุนต่อชิ้น/เหมาล็อต สินค้าสั่งซื้อรอรับ และค่าส่งรวมหลายสินค้า
- **Pre-order ลูกค้า** แยกจากสินค้าที่ร้านสั่งซื้อรอรับ: รับจอง ระบุลูกค้า/ช่องทางติดต่อ มัดจำ รับชำระเพิ่ม นัดส่ง แก้ไข ค้นหา กรองสถานะ ส่งมอบ และยกเลิกพร้อมบันทึกคืนเงิน
- ขายสินค้า พร้อมค่าส่ง ค่ากลาง กำไรประมาณ มัดจำ และการผ่อนชำระ
- รายรับ–รายจ่าย พร้อมค้นหา กรองประเภท/เดือน สถิติสินค้า และรายงานกำไร
- สำรอง/นำเข้า JSON รองรับข้อมูลเก่า รวมข้อมูลซ้ำ และล้างข้อมูลผ่านการยืนยัน
- วิเคราะห์แนวโน้มจากข้อมูลจริงด้วยกฎในเครื่อง บริการ AI ภายนอกยังไม่ได้เชื่อมต่อ จึงระบุไว้ชัดเจนในหน้าเว็บ

ข้อมูลอยู่ใน Firebase Firestore ที่ `stores/crazsix-store/data/{products,transactions,pendingOrders,preorders}` โดยคงข้อมูลเดิมและเพิ่มเอกสาร `preorders` แยกต่างหาก การบันทึกหลายเอกสารใช้ Firestore transaction และตรวจว่าข้อมูลยังตรงกับ snapshot ที่อ่านมา หากอีกเครื่องแก้ข้อมูลไปแล้ว ระบบจะปฏิเสธการเขียนทับและให้ตรวจข้อมูลล่าสุดก่อนลองใหม่ (ไม่รวมรายการให้อัตโนมัติ) การอัปเดตสดจะไม่ล้างฟอร์มที่กำลังกรอก ข้อมูลยังเป็นอาร์เรย์ต่อเอกสารตามระบบเดิมและยังมีข้อจำกัดขนาดเอกสารของ Firestore

## ขั้นตอน pre-order ลูกค้า

1. เข้าเมนู **Pre-order ลูกค้า → เพิ่ม pre-order ลูกค้า** ระบุลูกค้า สินค้า สี/ไซส์ จำนวน ราคาขาย วันนัดส่ง และมัดจำที่รับเงินจริง หนึ่งรายการรองรับสินค้า/สี/ไซส์หนึ่งแบบ หลายแบบให้สร้างแยกรายการ
2. อัปเดตสถานะ **รับจองแล้ว → สั่งให้ลูกค้าแล้ว → พร้อมส่งมอบ** พร้อมรับชำระเพิ่มได้หลายครั้ง ระบบไม่หักหรือกันสต็อกตอนรับจอง
3. เมื่อรับเงินครบ ให้ส่งมอบด้วยวิธีใดวิธีหนึ่ง: **ของที่จัดหาเฉพาะลูกค้า** ระบุต้นทุนจริง โดยไม่ผ่านสต็อก หรือ **นำสินค้าจากสต็อก** เลือกตัวเลือกสินค้าให้ตรง ระบบตรวจจำนวนแล้วหักสต็อก
4. หากต้นทุนของที่จัดหาเฉพาะลูกค้าเคยบันทึกเป็นรายจ่ายแล้ว ให้เลือกช่องที่ระบุไว้เพื่อไม่ลงรายจ่ายซ้ำ ไม่เช่นนั้นระบบจะลงต้นทุนในวันที่ส่งมอบ ค่าส่งและค่ากลางที่กรอกจะลงเพิ่มในวันส่งมอบ
5. ยกเลิกได้ก่อนส่งมอบ หากเคยรับเงินแล้วต้องคืนเต็มจำนวนและยืนยันว่าได้คืนเงินจริง ระบบบันทึกรายจ่ายคืนเงินและเก็บประวัติไว้ การบันทึกนี้ไม่ได้โอนเงินให้ลูกค้า

เงินมัดจำ/รับชำระนับเป็นกระแสเงินสดในวันที่รับ ส่วนยอดขาย pre-order (`transactions.type = "preorder"`) ใช้สรุปจำนวนขายและกำไรในวันที่ส่งมอบ โดยไม่บวกเงินรับซ้ำ และไม่ปะปนกับการผ่อนชำระ รายการบัญชีที่เชื่อมกับ pre-order เปิดกลับไปจัดการที่คำสั่งซื้อแทนการลบแยก

ไฟล์สำรองเวอร์ชัน 4 รวม pre-order และตรวจรหัสซ้ำ ยอดชำระ/คืนเงิน และสถานะกับบัญชี ยังนำเข้าไฟล์เก่าที่ไม่มี pre-order ได้ โดยการนำเข้าจะแทนที่ข้อมูลทั้งหมดรวมถึง pre-order ปัจจุบัน

## เปิดในเครื่อง

```bash
npm ci
npm run serve
```

เปิด http://127.0.0.1:4173 — เซิร์ฟเวอร์นี้ให้บริการหน้าแอปจริงซึ่งเชื่อมข้อมูล Firebase ตามค่าที่ตั้งไว้

## ทดสอบ

```bash
npx playwright install chromium
npm test
```

ชุดทดสอบแทนที่ Firebase ด้วยฐานข้อมูลจำลองก่อนโหลดแอป และบล็อกคำขอภายนอก จึงไม่แก้ข้อมูลร้านจริง ครอบคลุมสต็อก การขาย ผ่อนชำระ pre-order ทั้งวงจร การบันทึกล้มเหลว/กดซ้ำ การเขียนทับจากอีกเครื่อง สำรองข้อมูล วันที่กรุงเทพฯ และหน้าจอมือถือ รวมทั้งทดสอบโค้ดชั้น Firestore จริงโดยแทนเฉพาะ SDK ด้วยตัวจำลอง

## Deploy

```bash
npx firebase-tools deploy --only hosting --project crazsix-stock
```

Firebase runs `npm run build` before each deployment. The build copies only the ten browser assets explicitly listed in `scripts/build.js` into `dist/`. Git metadata, tests, tools, packages, documentation and rules are never included. HTML, CSS and JavaScript revalidate their cached version on every request.

ตั้งค่า Firebase ที่ `js/firebase-config.js` และชั้นข้อมูลที่ `js/firebase-service.js` ดูการตั้งค่าเดิมเพิ่มเติมที่ [FIREBASE_SETUP.md](FIREBASE_SETUP.md)

## ข้อจำกัดการเข้าถึงข้อมูล

`firestore.rules` ในโครงการยังเป็นกฎเดิมที่เปิดให้อ่านและเขียน และแอปยังไม่มีระบบเข้าสู่ระบบ การเปลี่ยนแปลงครั้งนี้ไม่ได้ตั้งค่าผู้ดูแลหรือ deploy กฎใหม่ ต้องกำหนดบัญชีและสิทธิ์ผู้ดูแลก่อนใช้เก็บข้อมูลลูกค้าที่ต้องจำกัดการเข้าถึง
