# Crazsix Store Workspace

เว็บจัดการสต็อกเสื้อผ้า การขาย และบัญชีร้าน Crazsix พร้อมหน้าตา Liquid Glass ที่รองรับเดสก์ท็อปและมือถือ

เว็บไซต์: https://crazsix-stock.web.app

## ฟีเจอร์

- ภาพรวมมูลค่าสต็อก เงินเข้า–ออก 6 เดือน สินค้าใกล้หมด สินค้ารอรับ และยอดค้างชำระ
- สินค้าหลายสี/ไซส์ แยกมือหนึ่ง–มือสอง รูปแยกตามสี เพิ่มหลายสินค้าและเติมสต็อกแบบต้นทุนเฉลี่ย
- ต้นทุนต่อชิ้น/เหมาล็อต สินค้าสั่งซื้อรอรับ และค่าส่งรวมหลายสินค้า
- **Pre-order ลูกค้า** แยกจากสินค้าที่ร้านสั่งซื้อรอรับ: รับจอง ระบุลูกค้า/ช่องทางติดต่อ มัดจำ รับชำระเพิ่ม นัดส่ง แก้ไข ค้นหา กรองสถานะ ส่งมอบ และยกเลิกพร้อมบันทึกคืนเงิน
- ขายสินค้า พร้อมค่าส่ง ค่ากลาง กำไรประมาณ มัดจำ และการผ่อนชำระ
- รายรับ–รายจ่าย พร้อมค้นหา กรองประเภท/เดือน สถิติสินค้า และรายงานกำไร
- สำรอง/นำเข้า JSON รองรับข้อมูลเก่า รวมข้อมูลซ้ำ และล้างข้อมูลผ่านการยืนยัน
- วิเคราะห์แนวโน้มจากข้อมูลจริงด้วยกฎในเครื่อง บริการ AI ภายนอกยังไม่ได้เชื่อมต่อ จึงระบุไว้ชัดเจนในหน้าเว็บ

ข้อมูลอยู่ใน Firebase Firestore ที่ `stores/crazsix-store/data/{products,transactions,pendingOrders,preorders,adCampaigns,adWallet,shipments}` โดยคงข้อมูลเดิมและเพิ่มเอกสาร `preorders` แยกต่างหาก การบันทึกหลายเอกสารใช้ Firestore transaction และตรวจว่าข้อมูลยังตรงกับ snapshot ที่อ่านมา หากอีกเครื่องแก้ข้อมูลไปแล้ว ระบบจะปฏิเสธการเขียนทับและให้ตรวจข้อมูลล่าสุดก่อนลองใหม่ (ไม่รวมรายการให้อัตโนมัติ) การอัปเดตสดจะไม่ล้างฟอร์มที่กำลังกรอก ข้อมูลยังเป็นอาร์เรย์ต่อเอกสารตามระบบเดิมและยังมีข้อจำกัดขนาดเอกสารของ Firestore

## ขั้นตอน pre-order ลูกค้า

1. เข้าเมนู **Pre-order ลูกค้า → เพิ่ม pre-order ลูกค้า** ระบุลูกค้า สินค้า สี/ไซส์ จำนวน ราคาขาย วันนัดส่ง และมัดจำที่รับเงินจริง หนึ่งรายการรองรับสินค้า/สี/ไซส์หนึ่งแบบ หลายแบบให้สร้างแยกรายการ
2. อัปเดตสถานะ **รับจองแล้ว → สั่งให้ลูกค้าแล้ว → พร้อมส่งมอบ** พร้อมรับชำระเพิ่มได้หลายครั้ง ระบบไม่หักหรือกันสต็อกตอนรับจอง
3. เมื่อรับเงินครบ ให้ส่งมอบด้วยวิธีใดวิธีหนึ่ง: **ของที่จัดหาเฉพาะลูกค้า** ระบุต้นทุนจริง โดยไม่ผ่านสต็อก หรือ **นำสินค้าจากสต็อก** เลือกตัวเลือกสินค้าให้ตรง ระบบตรวจจำนวนแล้วหักสต็อก
4. หากต้นทุนของที่จัดหาเฉพาะลูกค้าเคยบันทึกเป็นรายจ่ายแล้ว ให้เลือกช่องที่ระบุไว้เพื่อไม่ลงรายจ่ายซ้ำ ไม่เช่นนั้นระบบจะลงต้นทุนในวันที่ส่งมอบ ค่าส่งและค่ากลางที่กรอกจะลงเพิ่มในวันส่งมอบ
5. ยกเลิกได้ก่อนส่งมอบ หากเคยรับเงินแล้วต้องคืนเต็มจำนวนและยืนยันว่าได้คืนเงินจริง ระบบบันทึกรายจ่ายคืนเงินและเก็บประวัติไว้ การบันทึกนี้ไม่ได้โอนเงินให้ลูกค้า

เงินมัดจำ/รับชำระนับเป็นกระแสเงินสดในวันที่รับ ส่วนยอดขาย pre-order (`transactions.type = "preorder"`) ใช้สรุปจำนวนขายและกำไรในวันที่ส่งมอบ โดยไม่บวกเงินรับซ้ำ และไม่ปะปนกับการผ่อนชำระ รายการบัญชีที่เชื่อมกับ pre-order เปิดกลับไปจัดการที่คำสั่งซื้อแทนการลบแยก

ไฟล์สำรองเวอร์ชัน 10 รวมประวัติเติมเงินที่ผูกแคมเปญและงบที่เพิ่ม สถานะรอส่งและประวัติพัสดุ งบแอดต่อวัน ประวัติเติมเงิน Ads Manager แหล่งชำระค่าแอด ขนาดอก/ความยาวจริง pre-order แคมเปญยิงแอดหลายสินค้า และส่วนแบ่งค่าแอดแต่ละรายการ ตรวจรหัสซ้ำ ยอดชำระ/คืนเงิน สถานะกับบัญชี และความสัมพันธ์ของแคมเปญ ยังนำเข้าไฟล์เก่าได้ โดยการนำเข้าจะแทนที่ข้อมูลทุกชนิดรวมถึงแคมเปญและประวัติเติมเงินปัจจุบัน

## ยิงแอดและต้นทุนสินค้า

1. เข้า **ยิงแอด → เพิ่มแคมเปญยิงแอด** หรือกด **ยิงแอด** ข้างสินค้าในหน้าสต็อก เลือกสินค้าแรกแล้วติ๊กสินค้าเพิ่มเติมได้หลายรายการในแคมเปญเดียว (รวมทุกสี/ไซส์) ระบุชื่อ ช่องทาง วันเริ่ม งบ เป้าขายรวมทุกสินค้า และเปอร์เซ็นต์กำไรที่จะเก็บต่อ แนบลิงก์โฆษณาและโน้ตกลุ่มเป้าหมายได้
   เลือกระยะเวลา **ยิงต่อเนื่องจนงบหมด** ได้โดยไม่ต้องระบุวันสิ้นสุด เมื่อค่าแอดที่บันทึกรวมถึงงบ จะแสดงสถานะงบหมดและงานติดตาม เพิ่มงบแล้วสถานะกลับมาเปิดใช้งานได้ แคมเปญที่ตั้งพัก/จบ/ยกเลิกจะคงสถานะนั้น หรือเลือก **กำหนดวันสิ้นสุด** เพื่อใช้แบบเดิม แคมเปญเก่ายังคงวันสิ้นสุดเดิมจนกว่าจะแก้ไข
2. **งบต่อชิ้น = งบแคมเปญ ÷ เป้าขายรวมทุกสินค้า** ตารางวางราคาสมมติแบ่งเป้าจำนวนเท่ากันระหว่างสินค้าที่แนบ แสดงต้นทุนซื้อ + งบแอดต่อชิ้นจากทุกแคมเปญที่เปิดใช้งานหรือยังไม่เริ่ม พร้อมกำไรคาดการณ์ตามราคาขายที่ตั้งไว้ ยังไม่รวมค่าส่ง/ค่ากลาง หากขายไม่ถึงเป้า ค่าแอดจริงต่อชิ้นจะสูงขึ้น
3. บันทึก **ค่าแอดที่จ่ายจริง** แต่ละครั้งพร้อมวันที่/หมายเหตุ ระบบสร้างรายจ่าย `ค่าโฆษณาสินค้า` ครั้งเดียว งบแผนยังไม่ใช่เงินที่จ่าย ค่าแอดเป็นต้นทุนโฆษณาของสินค้าแยกจากต้นทุนซื้อ ไม่แก้ `variant.cost` หรือเพิ่มมูลค่าสินค้าคงเหลือ เพื่อไม่หักซ้ำเมื่อขาย
   ค่าใช้จ่ายแต่ละครั้งแบ่งเท่ากันให้สินค้าที่แนบขณะบันทึก เก็บเป็น `adAllocations` และกระจายเศษสตางค์ให้รวมตรงยอดจ่าย เช่น 100 บาทกับ 2 สินค้า = สินค้าละ 50 บาท การเพิ่มสินค้าในภายหลังไม่เปลี่ยนส่วนแบ่งค่าแอดเก่า แคมเปญรุ่นเก่าที่ผูกสินค้าเดียวใช้ต้นทุนเดิมทั้งหมดกับสินค้านั้น นำสินค้าที่มีต้นทุนหรือยอดขายผูกอยู่ออกไม่ได้ แต่เพิ่มสินค้าได้ ยอดขายและกำไรสินค้าแต่ละตัวคำนวณเฉพาะสินค้านั้น จึงไม่ซ้ำกับสินค้าอื่นในแคมเปญ
4. ตอนขายเลือกแคมเปญ หรือผูกยอดขายย้อนหลังในแคมเปญได้ แต่ละยอดขายผูกได้หนึ่งแคมเปญ รวมยอดขายผ่อนและ pre-order ที่ส่งมอบจากสต็อกแล้ว รายการ pre-order ที่จัดหาโดยไม่ผ่านสต็อกไม่มีรหัสสินค้าคงคลังจึงไม่อยู่ในตัวเลือกนี้ ยอดขายไม่ถูกจัดว่าเกิดจากโฆษณาโดยอัตโนมัติตามวันที่
5. แสดงยอดขายที่ผูก กำไรก่อนแอด กำไรหลังหักค่าแอดจริง ค่าแอดจริงต่อชิ้น และ **ROAS = ยอดขายที่ผูก ÷ ค่าแอดจริง** หากยังไม่จ่ายแอดจะแสดง ROAS เป็นขีด หากยังไม่ขายจะไม่หารต้นทุนด้วยศูนย์ รายละเอียดสินค้าแสดงกำไรจากยอดขายทั้งหมดของสินค้านั้นหักค่าแอดทุกแคมเปญ
6. **เงินแนะนำเก็บสะสม = max(0, กำไรตามเงินรับจริงหลังหักแอด) × เปอร์เซ็นต์ที่ตั้ง** เริ่มต้น 20% ปรับได้ 0–100% โดยหักยอดผ่อนที่ยังไม่ได้รับออกจากกำไรขายก่อน เช่น ขาย 1,000 ต้นทุน/ค่าส่ง/ค่ากลางรวม 400 จ่ายแอด 200 และรับเงินครบ จะเหลือกำไร 400 แนะนำเก็บ 80 บาท หากรับเงินไม่พอคืนต้นทุนและค่าแอด แนะนำเก็บ 0 บาท ยอดแนะนำรวมทุกแคมเปญไม่เกินกำไรรวมตามเงินรับจริงหลังแอด ตัวเลขนี้เป็นแผนสะสม ไม่ใช่บัญชีเงินที่แยกเก็บแล้วหรือการรับประกันผลตอบแทน
7. แก้ไข/พัก/จบ/ยกเลิกแคมเปญได้ แสดงสถานะตามวันที่ ช่วงวันที่รวมวันสุดท้าย เตือนงบเกินและครบกำหนดในหน้าแคมเปญและงานที่ต้องติดตาม ค้นหา กรอง และส่งออก CSV เฉพาะรายการที่แสดงได้ ลบแคมเปญได้เมื่อไม่มีค่าใช้จ่ายหรือยอดขายผูกอยู่เท่านั้น ค่าแอดที่กรอกผิดลบได้จากประวัติพร้อมคำนวณยอดใหม่

**ค่าแอดรายวัน:** ในแต่ละแคมเปญเปิด “บันทึกค่าแอดรายวัน” เลือกวันที่และกรอกยอดใช้เพิ่มที่ยังไม่ได้บันทึก ระบบแสดงยอดเดิมและยอดรวมหลังบันทึก รวมหลายรายการในวันเดียวกันเป็นตารางรายวัน แยกใช้เครดิต/จ่ายตรง และส่งออก CSV รายแคมเปญได้ ยอดรวมและต้นทุนใช้ค่าแอดจริง ไม่ใช่งบที่ตั้งไว้ หากกรอกผิดลบรายการจากประวัติค่าแอดเพื่อคำนวณใหม่

**งบต่อวัน:** กรอกงบยิงแอดต่อวันได้ในฟอร์มสร้าง/แก้ไขแคมเปญ หรือเว้นว่างสำหรับแคมเปญเดิม ระบบแสดงจำนวนวันที่งบคงเหลือพอโดยประมาณ = งบที่เหลือ ÷ งบต่อวัน และแยกค่าแอดใช้จริงวันนี้จากรายการที่บันทึก การตั้งงบไม่ลงรายจ่ายอัตโนมัติ ส่วนงบเฉลี่ยจากวันเริ่ม–สิ้นสุดยังคำนวณจากแผนเดิม

**เติมเงินเข้าแคมเปญ:** ในแต่ละแคมเปญกด “เติมเงินเข้าแคมเปญ / ประวัติ” ระบุยอดที่เพิ่งเติมจริง วันที่ และหมายเหตุ ระบบเพิ่มงบแคมเปญและเครดิต Ads Manager ครั้งเดียว เช่น งบเดิม 500 เติม 200 เป็นงบ 700 ไม่ต้องบันทึกยอดเดียวกันซ้ำในกระเป๋ากลาง ประวัติแสดงทั้งในแคมเปญและกระเป๋ากลางโดยอ้างรายการเดียวกัน การลบรายการผิดจะลดงบและเครดิตกลับ โดยไม่เปลี่ยนค่าแอดที่ใช้จริง หากแก้งบเองจนต่ำกว่ายอดเติมที่จะลบ ระบบให้ตรวจงบก่อน แคมเปญที่มีประวัติเติมเงินไม่สามารถลบทิ้งได้ ให้พักหรือจบแคมเปญแทน

**เติมเงิน Ads Manager:** บันทึกจำนวนเงิน วันที่ และหมายเหตุได้ในกระเป๋ากลางร่วมกันทุกแคมเปญ แสดงยอดเติมสะสม ยอดใช้เครดิต และเครดิตคงเหลือ พร้อมประวัติ ลบรายการผิด และ CSV ตอนบันทึกค่าแอดเลือกแหล่งชำระว่าใช้เครดิตที่เติมไว้หรือจ่ายตรง รายการเก่าไม่หักกระเป๋าอัตโนมัติ การลบค่าแอดที่ผิดคืนเครดิตตามบันทึก ส่วนการลบยอดเติมไม่ได้ขอคืนเงินจริง ยอดติดลบแสดงคำเตือนให้ตรวจข้อมูลที่อาจยังบันทึกไม่ครบ

ยอดเติมเงินเป็นบันทึกติดตามเครดิตแยกจากบัญชี ไม่ใช่รายจ่ายเพิ่ม การเติมจากกระเป๋ากลางไม่เพิ่มงบรวมของแคมเปญ บัญชีเดิมยังนับรายจ่ายค่าแอดเมื่อบันทึกค่าใช้จริง ไม่ใช่วันที่โอนเงินเติม ดังนั้นตัวเลขนี้ไม่ได้ใช้กระทบยอดเงินออกจากธนาคารตามวันเติม ระบบไม่เชื่อมต่อหรือดึงยอดจาก Ads Manager โดยตรง

ข้อมูลแคมเปญอยู่ในเอกสาร `stores/crazsix-store/data/adCampaigns` และประวัติเติมเงินอยู่ใน `stores/crazsix-store/data/adWallet` รายการค่าแอดและยอดขายเชื่อมด้วย `adCampaignId` โดย `adWalletFunded` ระบุค่าแอดที่ใช้เครดิต บันทึกพร้อมบัญชีด้วย transaction และตรวจการแก้ทับจากอุปกรณ์อื่น

รายงานตามช่วงวันที่แสดงกำไรขายก่อนแอดและหลังหักค่าแอด **ตามวันที่จ่ายในช่วงที่เลือก** เงินจ่ายจริงรวมค่าแอดแล้วจึงไม่หักซ้ำจากเงินสดสุทธิ กราฟ/รายงานขายเดิมยังเป็นกำไรก่อนค่าแอด สำรอง JSON รวมแคมเปญและความสัมพันธ์ทั้งหมด

เมนูนี้เป็นเครื่องมือวางแผนและบันทึกผลในร้าน ยังไม่ได้เชื่อม API หรือส่งโฆษณาจริงไป Facebook, TikTok หรือแพลตฟอร์มอื่น ยอดใช้จ่ายต้องบันทึกตามจริง

## เครื่องมือจัดการร้านเพิ่มเติม

- **งานที่ต้องติดตาม** รวมสินค้าหมด/ใกล้หมด สินค้าที่ร้านสั่งรอรับ pre-order ลูกค้า และยอดผ่อนค้าง เรียงงานเร่งด่วนก่อน ค้นหา/กรอง และเปิดกลับไปยังหน้าจัดการได้
- **รับของเข้าบางส่วน** ในหน้าสต็อก → รอรับของ ระบุ “รับครั้งนี้” เช่น สั่ง 5 ได้มา 2 ระบบเติมสต็อก 2 และคงรายการรอรับอีก 3 พร้อมต้นทุนเฉลี่ยถ่วงน้ำหนัก ไม่ลงต้นทุนซื้อซ้ำ ค่าส่งบันทึกตามครั้งที่รับจริง
- **แก้ไขรายการบัญชีที่กรอกเอง** กดแก้ไขข้างรายการ แก้ประเภท หมวด รายละเอียด จำนวนเงิน และวันที่ โดยคงรหัสเดิม ระบบปฏิเสธหากรายการถูกอีกเครื่องแก้ระหว่างกรอก รายการอัตโนมัติที่เชื่อมกับสินค้า/ออเดอร์จัดการจากขั้นตอนที่เกี่ยวข้อง
- **รายงานตามช่วงวันที่** แสดงเงินรับจริง เงินจ่ายจริง เงินสดสุทธิ และกำไรจากการขายแยกกัน พร้อม CSV ตามช่วงวันที่ กราฟและตารางด้านล่างยังเป็นภาพรวมทุกช่วงเวลา
- **ส่งออก CSV** สต็อก บัญชี และ pre-order ผ่านเมนูจัดการข้อมูลท้ายหน้า หรือส่งออกเฉพาะบัญชีตามตัวกรองที่ใช้อยู่ รองรับภาษาไทยและป้องกันข้อความลูกค้าถูกประมวลผลเป็นสูตร CSV ใช้วิเคราะห์ข้อมูล ส่วนการกู้คืนระบบใช้ JSON backup

การลบรายการบัญชีเดิมไม่ใช่การคืนสินค้า และไม่ปรับสต็อกหรือโอนคืนเงิน ระบบแสดงผลกระทบก่อนยืนยัน ส่วนรายการ pre-order ต้องจัดการจากหน้า pre-order เพื่อรักษายอดชำระ/คืนเงินให้ตรงกัน

## รอส่งและการจัดส่ง

- การขายใหม่ทั้งเงินสดและผ่อนชำระจะมีสถานะ **รอส่ง** หลังตัดสต็อกและบันทึกยอดขาย กรอกผู้รับ/เลขคำสั่งซื้อไว้ตอนขายได้ ยอดขายเก่าที่ยังไม่มีสถานะไม่ถูกนำเข้าคิวอัตโนมัติ ส่วน pre-order ที่กดยืนยันส่งมอบแล้วใช้ประวัติ pre-order ตามเดิม
- เข้าเมนู **รอส่ง** หรือปุ่มรอส่งในหน้าขาย เลือกหลายรายการของผู้รับเดียวกัน ระบุจำนวนที่จะส่งแต่ละรายการ วันที่ส่ง ขนส่ง เลขพัสดุ และหมายเหตุ แล้วกด **ส่งสินค้าแล้ว** รองรับการส่งบางส่วน โดยเหลือคิวเฉพาะจำนวนที่ยังไม่ส่ง รายการผ่อนจะแสดงยอดค้างชำระประกอบการตัดสินใจ
- การส่งเปลี่ยนเฉพาะสถานะ ไม่ตัดสต็อก รับเงิน หรือบันทึกค่าส่งซ้ำ สถานะมี รอส่ง / ส่งบางส่วน / ส่งสินค้าแล้ว การยกเลิกการบันทึกส่งจะคืนจำนวนเข้าคิวและเก็บประวัติการยกเลิก ไม่คืนเงินหรือสต็อก
- เก็บพัสดุในเอกสาร `shipments` อ้างรายการขายด้วย `saleId` และจำนวนส่ง บันทึกพร้อมสถานะใน `transactions` แบบ atomic ตรวจป้องกันกดซ้ำหรือเขียนทับอีกเครื่อง สำรอง JSON ตรวจความสัมพันธ์และจำนวนส่ง ส่วน CSV การจัดส่งส่งออกได้จากเมนูรอส่ง รายการขายที่มีประวัติจัดส่งไม่สามารถลบจากบัญชีแยกได้
- งานที่ต้องติดตามแสดงรายการขายรอส่งพร้อมลิงก์ไปเลือกสินค้า และแจ้งเตือนสต็อกใกล้หมด/หมดเฉพาะมือหนึ่ง ไม่แจ้งสินค้ามือสองที่เหลือหนึ่งชิ้นหรือหมด

## การจัดการสต็อก

หน้าสต็อกมี 5 แท็บ: รายการสินค้า, เพิ่ม/เติมสต็อก, รอรับของ, บันทึกค่าส่ง และตรวจนับสต็อก

สินค้าแต่ละตัวเลือกบันทึก **อกและความยาวหน่วยนิ้ว** ได้ในฟอร์มเพิ่มสินค้า เพิ่มสี/ไซส์ สั่งซื้อรอรับของ และแก้ไขสินค้า เว้นว่างได้ รองรับทศนิยม 2 ตำแหน่ง ควรวัดอกด้วยวิธีเดียวกันทุกชิ้น ระบบเก็บค่าที่กรอกโดยไม่แปลงเป็นรอบอกอัตโนมัติ สำหรับมือสองที่ป้ายไซส์เดียวกันแต่ขนาดจริงต่างกัน ให้แยกแถว เช่น M อก 22.5 ยาว 28 กับ M อก 23 ยาว 29 ระบบแยกจำนวนและต้นทุนให้ หากสี ไซส์ สภาพ และขนาดจริงตรงกันจึงจะรวมสต็อก ข้อมูลเดิมที่ไม่ได้กรอกขนาดยังคงเป็นตัวเลือกไม่ระบุขนาด และไม่รวมกับตัวเลือกที่ระบุขนาดแล้ว

ขนาดจริงแสดงในรายการสต็อกและตัวเลือกขาย/เติมสต็อก/รับของ รวมถึง CSV และ JSON backup การขายเก็บขนาด ณ เวลาขายไว้ในประวัติ แม้แก้ขนาดของสต็อกภายหลัง

- เติมสต็อก / เพิ่มสีไซส์: เลือกตัวเลือกสินค้าเดิม แล้วกด “เพิ่มสี / ไซส์ของสินค้านี้” เพื่อเพิ่มแถวสีหรือไซส์ใหม่ใต้สินค้าเดิมได้ทันที ลบแถวที่ไม่ต้องการเติมออกก่อนบันทึก ถ้าตัวเลือกตรงกับที่มีอยู่ ระบบรวมจำนวนและคำนวณต้นทุนเฉลี่ย โดยแยกมือหนึ่งและมือสอง
- สั่งซื้อรอรับของ: เลือกสินค้าเดิมจากรายการ แล้วกรอกสี/ไซส์ใหม่ หรือใช้ปุ่ม “เพิ่มสี / ไซส์ของสินค้านี้” เพิ่มหลายตัวเลือกในครั้งเดียว รายการผูกกับรหัสสินค้าแม้เปลี่ยนชื่อภายหลัง และจะเพิ่มตัวเลือกเข้าสต็อกเมื่อยืนยันรับของเท่านั้น
- การเพิ่มหรือลบแถวเติมสต็อกคงต้นทุนและราคาที่กรอกในแถวอื่นไว้ หากบันทึกไม่สำเร็จ ฟอร์มยังคงข้อมูลเพื่อให้ลองใหม่ได้

- รายการสินค้า: ค้นหาร่วมกับตัวกรองมีของ/ใกล้หมด/หมด และมือหนึ่ง/มือสอง เรียงตามชื่อ จำนวน หรือมูลค่า ยอดรวมและ CSV “ส่งออกที่แสดง” คิดเฉพาะตัวเลือกที่ตรงตัวกรอง
- เพิ่ม/เติมสต็อก: ตรวจทุกแถวก่อนเปลี่ยนข้อมูล ไม่ตัดทศนิยมของจำนวนทิ้งเงียบ ๆ ไม่ข้ามสินค้าที่ถูกลบระหว่างกรอก และตรวจค่าส่งก่อนบันทึก รายจ่ายต้นทุนเหมาล็อตกระจายเป็นสตางค์ให้ผลรวมตรงยอดล็อต ส่วนต้นทุนเฉลี่ยในสต็อกเก็บความละเอียดเดิม
- แก้ไขสินค้า: ป้องกันตัวเลือกสี/ไซส์/สภาพที่มีขนาดจริงตรงกันซ้ำและป้องกันแก้ทับข้อมูลล่าสุดจากอีกเครื่อง การเปลี่ยนชื่อมีผลทุกตัวเลือกในกลุ่มนั้น ช่องต้นทุนรองรับค่าถัวเฉลี่ยหลายตำแหน่ง
- ตรวจนับสต็อก: เลือกสินค้า กรอกจำนวนจริงกับเหตุผล แสดงผลต่างก่อนบันทึก เก็บยอดก่อน/หลัง เวลา และเหตุผล รวมทั้งการปรับจำนวนจากหน้าแก้ไข โดยไม่เปลี่ยนต้นทุนต่อชิ้นหรือสร้างรายการบัญชี
- ประวัติปรับยอดอยู่ใน `variants[].adjustments` และสำรองพร้อม JSON ไม่ใช่ประวัติการเคลื่อนไหวซื้อ/ขายทั้งหมด เมื่อลบตัวเลือกสินค้าประวัตินี้จะถูกลบด้วย การรวมสินค้าซ้ำจะเก็บประวัติของทั้งสองตัวเลือกไว้
- บันทึกค่าส่ง: ตรวจจำนวนเต็ม ยอดเงิน และวันที่ก่อนบันทึก จำนวนสินค้าที่แนบต้องไม่เกินสต็อกปัจจุบัน

```bash
npx playwright install chromium

```

ชุดทดสอบแทนที่ Firebase ด้วยฐานข้อมูลจำลองก่อนโหลดแอป และบล็อกคำขอภายนอก จึงไม่แก้ข้อมูลร้านจริง ครอบคลุมสต็อก การขาย ผ่อนชำระ pre-order ทั้งวงจร การบันทึกล้มเหลว/กดซ้ำ การเขียนทับจากอีกเครื่อง สำรองข้อมูล วันที่กรุงเทพฯ และหน้าจอมือถือ รวมทั้งทดสอบโค้ดชั้น Firestore จริงโดยแทนเฉพาะ SDK ด้วยตัวจำลอง

## Deploy

```bash
npx firebase-tools deploy --only hosting --project crazsix-stock
```

Firebase runs `npm run build` before each deployment. The build copies only the seventeen browser assets explicitly listed in `scripts/build.js` into `dist/`. Git metadata, tests, tools, packages, documentation and rules are never included. HTML, CSS and JavaScript revalidate their cached version on every request.

ตั้งค่า Firebase ที่ `js/firebase-config.js` และชั้นข้อมูลที่ `js/firebase-service.js` ดูการตั้งค่าเดิมเพิ่มเติมที่ [FIREBASE_SETUP.md](FIREBASE_SETUP.md)

## ข้อจำกัดการเข้าถึงข้อมูล

`firestore.rules` ในโครงการยังเป็นกฎเดิมที่เปิดให้อ่านและเขียน และแอปยังไม่มีระบบเข้าสู่ระบบ การเปลี่ยนแปลงครั้งนี้ไม่ได้ตั้งค่าผู้ดูแลหรือ deploy กฎใหม่ ต้องกำหนดบัญชีและสิทธิ์ผู้ดูแลก่อนใช้เก็บข้อมูลลูกค้าที่ต้องจำกัดการเข้าถึง
